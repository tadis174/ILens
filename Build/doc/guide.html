Why ILens

When an AI agent needs to inspect a compiled .NET assembly, the usual fallback is to shell out through Bash to ildasm (an IL dump) or ilspycmd (a full C# decompile). Each invocation prints an entire file as text, and that text then lives in the agent's context as input tokens on every subsequent turn — thousands of tokens spent to answer one question about one class, paid again and again for the rest of the conversation.

Taskilspycmd costILens toolILens cost
List the public types in a namespace1,041,476 tokenslist_types1,196 tokens
See the API surface of one mid-sized class1,041,476 tokenssummarize_type895 tokens
Find which types expose a given method1,041,476 tokensfind_methods618 tokens

Measured against ICSharpCode.Decompiler.dll 9.1.0.7988 (about 2 MB, 741 public types) on 2026-07-18; token figures are character counts divided by 4, not a real tokenizer. The ilspycmd column is the same full-file dump on every row — every targeted task otherwise starts from that same whole-assembly cost.

ILens turns assembly inspection into bounded, targeted lookups instead of full-file dumps — which is what makes it cheap enough to leave registered as an always-available tool.

Overview and scope

ILens is a single self-contained executable that speaks the Model Context Protocol over stdio and exposes read-only tools in four groups: discovery (find types and methods), inspection (summarize and cross-reference), decompilation (recover C# source), and comparison (diff two builds). Its trust posture is narrow: it loads assemblies only from directories you name with --allow-root, never writes, never opens a network port, and ships as one binary with no separate runtime to install.

Scope. ILens is built for inspecting C# assemblies, and its output is C#. The metadata-driven tools — list_types, search_types, list_members, find_methods, and analyze — read language-agnostic metadata and work on an assembly produced by any .NET language. The decompiling tools — decompile_type, decompile_method, decompile_property, decompile_event, and summarize_type — always emit C#; an assembly compiled from F#, VB.NET, or C++/CLI still loads, but constructs the source language has and C# does not may render unfaithfully.

Built on ILSpy

ILens would be nothing without ILSpy. The decompiler, the analyzer infrastructure, and the type system that lets ILens describe a .NET assembly in C# terms at all are upstream work by the ILSpy team. ILens links ICSharpCode.Decompiler for the decompiler proper and ICSharpCode.ILSpyX for the analyzer infrastructure, and is — candidly — a thin MCP shim on top of more than a decade of careful work.

That upstream is MIT-licensed, which is the only reason ILens can exist. If ILens is useful to you, please consider giving ILSpy a star — the team earned it.

To be clear: bug reports and feature requests about ILens belong on the ILens issue tracker, not ILSpy's. The upstream maintainers shouldn't have to inherit downstream problems — they have enough work of their own.

Installation

System requirements: Windows 10/11, x64. The binary is self-contained — there is no separate .NET runtime to install.

Recommended: winget

winget install Tadis.ILens

A standard winget portable install: it downloads the release ZIP, extracts it under %LOCALAPPDATA%\Microsoft\WinGet\Packages\Tadis.ILens_*\, and registers ilens as a command alias in %LOCALAPPDATA%\Microsoft\WinGet\Links\ (already on your user PATH from any prior winget portable use). No admin elevation needed.

Integrating with Claude Code

Add an entry to .mcp.json in your project root. The installer puts ilens on your PATH, so the command field references the binary by name — no full path needed:

{
  "mcpServers": {
    "ilens": {
      "command": "ilens",
      "args": [
        "--allow-root", "C:\\path\\to\\dlls"
      ]
    }
  }
}

A first install needs a full restart, not just a new session. Two independent gates must clear before a freshly-installed ilens actually launches as an MCP server.

PATH propagation. Windows captures a process's PATH from the registry when the process starts, and later registry changes do not reach already-running processes. If ilens is a brand-new entry on user PATH — true for a first-ever winget portable install (which adds %LOCALAPPDATA%\Microsoft\WinGet\Links\) and for any install.ps1 run (which adds %LOCALAPPDATA%\Programs\ILens\) — an already-running Claude app holds a stale environment, and every Claude Code session inside it inherits that stale environment. A later winget upgrade of an already-installed package doesn't touch PATH and doesn't trip this gate.

MCP-server registration. Claude Code reads .mcp.json only at session start; editing it inside a running session does not register the new server in that session.

Recovering takes both: fully exit and relaunch Claude app so the new app process inherits the current registry PATH, and start a new Claude Code session in the relaunched app. Existing sessions survive a Claude app restart with their original environments intact, so a resumed session won't pick up either change.

Recipe for a first install via the Claude app: close Claude app entirely → install via winget (or install.ps1) → relaunch Claude app → start a new Claude Code session.

Each --allow-root flag adds a directory tree from which assemblies may be loaded. Tool calls supply the assembly path per request; the server validates that the path is inside one of the configured roots.

For the equivalent claude mcp add CLI command see Appendix D; for Claude Desktop see Appendix E.

Project-level guidance

Registering the server makes the tools available. A short hint in the consuming project's CLAUDE.md is what makes Claude actively prefer them over running dotnet / ildasm through Bash, reading assembly files directly, or web-searching for source. Drop this block into your project's CLAUDE.md and replace <allow-root> with the directory you configured:

## Inspecting .NET assemblies

Assemblies under `<allow-root>` are reachable through the `ilens` MCP server.
Prefer ILens tools over running `ildasm` / `ilspycmd` via Bash, reading assembly
files directly, or web-searching for source.

- Discovery: `search_types` (substring match), `list_types` (whole namespace),
  `find_methods` (signature search).
- Reading: `summarize_type` (public surface, no bodies), `list_members`
  (filtered surface), `decompile_type` (full C#), `decompile_method` (single
  method body), `decompile_property` / `decompile_event` (full property or
  event declaration with accessor bodies, by unprefixed name).
- Cross-references: `analyze` with `kind` set to one of `UsedBy`,
  `InstantiatedBy`, `ExposedBy`, `ExtensionMethods`, `AppliedTo`,
  `OverriddenBy`, `ImplementedBy`, `Uses`, `Implements`, `ReadBy`,
  `AssignedBy`. Valid kinds depend on the symbol category.
- Comparing two builds: `list_changed_types` (what differs between two
  assemblies), `compare_type` (per-type member and body diff),
  `compare_method` (one method's body as C# or IL).

Per-line walkthrough

  • The first paragraph is the load-bearing prefer-MCP rule. Without it, models default to Bash.
  • The discovery bullet routes "I don't know the full name" tasks to the right tool: a partial name goes to search_types, a known namespace goes to list_types, a method shape goes to find_methods.
  • The reading bullet escalates from cheapest to most expensive: summarize_type first, list_members when only part of the surface is needed, decompile_method for a single body (or decompile_property / decompile_event for a whole property or event without knowing the IL accessor prefix), decompile_type only when full source is required.
  • The analyze bullet enumerates the kind enum so the model picks values the schema accepts — using one that doesn't apply to the symbol category produces an error like Analysis kind 'ReadBy' is not valid for Method.
  • The comparison bullet is for "did this change between two builds?" work: start broad with list_changed_types, narrow to one type with compare_type, and read a single differing body with compare_method.

Security model

  • --allow-root flags are mandatory — with no roots configured, no assembly is loadable.
  • Every request validates that the assembly path is inside one of the configured roots; symbolic links and junctions are resolved to their real target first, so a link planted inside a root cannot point the loader outside it.
  • Path-traversal segments (..) are rejected outright.
  • Total memory is bounded by an aggregate budget (default 200 MB, set with --max-total-size <MB>): a load past the budget evicts least-recently-used assemblies, and a single assembly larger than the whole budget is refused.
  • All tools are read-only — no writes to assemblies, no shell-out, no network calls.
  • The server speaks stdio only; it does not open a network port.
  • The allow-root bounds which target assemblies can be inspected — it is not the boundary of every file ILens opens. Decompilation also reads the target's dependency assemblies (siblings in its directory, and .NET framework/runtime assemblies) as type-resolution context.

Tool reference

Every tool is read-only and takes at least one assembly path that must resolve inside a configured allow-root. Errors are returned as an error response of the form Error: <ExceptionType>: <Message>.

Discovery

find_methods read-only

Search an assembly for methods matching a signature, combining any of: name pattern, return type, parameter types, parameter count, declaring namespace, declaring type, declaring-type pattern, and accessibility. To list the methods of one known type, pass declaringType with its fully qualified name — the same form decompile_method's typeName takes; declaringTypePattern is the looser sibling that matches a substring of the short name.

assembly required
string — path to the assembly, inside an allow-root.
namePattern optional
string — case-insensitive substring on the method name.
returns optional
string — return-type pattern (short or full name; generics erased; [] for arrays).
parameterTypes optional
string[] — ordered parameter-type patterns; the method must have exactly this many parameters.
parameterCount optional
int? — exact parameter count; must agree with parameterTypes if both are given.
declaringNamespace optional
string — exact declaring namespace.
declaringType optional
string — exact fully qualified declaring type, e.g. System.IO.File; nested types take + or .. Errors if no such type exists, because an exact name asserts the type is real. Mutually exclusive with declaringTypePattern.
declaringTypePattern optional
string — case-insensitive substring on the declaring type's short name. Matching nothing is a legitimate empty result here, unlike declaringType.
accessibility optional
Public | PublicProtected | All — default PublicProtected.
limit optional
int? — cap on result lines; default 50.

Returns. A match count followed by one method per line, rendered as static? Type.Name(params) → ReturnType, sorted by declaring type then name, truncated at the limit with a marker. No methods match when nothing qualifies.

Errors.

  • Assembly path outside the allow-roots, or the file is missing.
  • Assembly larger than the memory budget.
  • parameterCount contradicts parameterTypes.Length.
  • declaringType and declaringTypePattern both supplied — they are mutually exclusive.
  • declaringType names a type that does not exist: Type not found: <name>.

See also: list_members, analyze.

list_allowed_roots read-only

List the directories from which assemblies can be loaded. Any assembly argument passed to another tool must point inside one of these.

(no parameters)
Reports server configuration only.

Returns. One root path per line, or No allowed roots configured. The server cannot load any assemblies.

Errors. None — this tool reads only the server's own configuration.

See also: list_types, search_types.

list_types read-only

List all types in a namespace, returned as fully qualified names. By default it hides compiler-generated noise — [CompilerGenerated] types, Roslyn synthetics (closures, display classes, iterator/async state machines, anonymous types, <PrivateImplementationDetails>), Unity/Burst source-generator output, and Burst direct-call wrapper nested types.

assembly required
string — path to the assembly, inside an allow-root.
namespaceName required
string — the namespace to list, e.g. System.IO.
excludeCompilerGenerated optional
bool — drop compiler-emitted types; default true.

Returns. A type count followed by fully qualified names, one per line, sorted. No types in namespace '<name>' when the namespace is empty or absent.

Errors.

  • Assembly path outside the allow-roots, or the file is missing.
  • Assembly larger than the memory budget.

See also: search_types, summarize_type.

search_types read-only

Search for types by name pattern — a case-insensitive substring matched against each type's short name (the namespace is not part of the match). Results come back as fully qualified names, so they feed straight into other tools. Hides the same compiler-generated noise as list_types by default.

assembly required
string — path to the assembly, inside an allow-root.
pattern required
string — substring matched against each type's short name, e.g. Stream.
excludeCompilerGenerated optional
bool — drop compiler-emitted types; default true.

Returns. A match count followed by fully qualified names (up to 50), with a truncation marker beyond that. No types match '<pattern>' when nothing qualifies.

Errors.

  • Assembly path outside the allow-roots, or the file is missing.
  • Assembly larger than the memory budget.

See also: list_types, list_members.

Inspection

analyze read-only

Run cross-reference analysis on a type or member — callers, instantiators, overrides, implementations, extension methods, attribute usage, field reads and assignments. Omit memberName to analyze the type itself.

assembly required
string — path to the assembly, inside an allow-root.
typeName required
string — fully qualified type name.
kind required
UsedBy | InstantiatedBy | ExposedBy | ExtensionMethods | AppliedTo | OverriddenBy | ImplementedBy | Uses | Implements | ReadBy | AssignedBy — valid values depend on the symbol category (type, method, property, field, event).
memberName optional
string — omit to analyze the type itself.
parameterCount optional
int? — disambiguates a method member by arity.
parameterTypes optional
string[] — disambiguates same-arity method overloads by type.
limit optional
int? — cap on result lines; default 50.

Returns. A header naming the analyzed symbol and the analysis kind, followed by fully qualified references, one per line, capped at the limit.

Errors.

  • Assembly path outside the allow-roots, or the file is missing.
  • Type or member not found.
  • The chosen kind is not valid for the resolved symbol category (e.g. Analysis kind 'ReadBy' is not valid for Method).
  • AppliedTo on a type that does not derive from System.Attribute.
  • ImplementedBy on a type that is not an interface.
  • parameterCount contradicts parameterTypes.Length.

See also: find_methods, decompile_method.

find_harmony_dependencies read-only

Extract the full reflective surface of a Harmony-patching assembly as JSON: every patch target (from [HarmonyPatch] attributes and from TargetMethod / TargetMethods bodies) and every reflective field access (AccessTools.Field, AccessTools.FieldRefAccess, Traverse.Field). Pair it with compare_method across two versions of a target assembly to answer "do these patches still bind?".

assembly required
string — path to the Harmony-patching assembly to scan, inside an allow-root.

Returns. Indented JSON of the shape { patches: [...], fieldAccesses: [...] }. Each patch carries its target type and member, optional parameter-type list, patch kind, a resolutionKind (TypedAttribute, StringTargeted, Attribute, TargetMethod, TargetMethods, or DynamicTargetMethod), and the patch site. Each field access carries its context type, field name, accessor kind, and patch site.

Errors.

  • Assembly path outside the allow-roots, or the file is missing.
  • Assembly larger than the memory budget.

See also: compare_method, analyze.

list_members read-only

List the members of a type, grouped by kind (methods, properties, fields, events). Returns one signature per line — no method bodies, no documentation strings. Cheaper than summarize_type when you only need part of the surface.

assembly required
string — path to the assembly, inside an allow-root.
typeName required
string — fully qualified type name.
kinds optional
(Method | Property | Field | Event)[] — omit to include all four.
accessibility optional
Public | PublicProtected | All — default PublicProtected.
namePattern optional
string — case-insensitive substring on the member name.
includeInherited optional
bool — include members from base types (stops at System.Object); default false.
limit optional
int? — cap on total lines across all kinds; default 100.

Returns. The type name followed by per-kind sections, each a count and one signature per line, truncated at the limit with a marker. No members on <type> match the filter when nothing qualifies.

Errors.

  • Assembly path outside the allow-roots, or the file is missing.
  • Type not found.
  • Assembly larger than the memory budget.

See also: summarize_type, find_methods.

summarize_type read-only

Summarize the public and protected API surface of a type — signatures only, no method bodies. Use it for a quick read of the available members, fields, and properties.

assembly required
string — path to the assembly, inside an allow-root.
typeName required
string — fully qualified type name.

Returns. The type rendered as C#, with non-public members removed and every method body stripped to a signature.

Errors.

  • Assembly path outside the allow-roots, or the file is missing.
  • Type not found.
  • Assembly larger than the memory budget.

See also: list_members, decompile_type.

Decompilation

decompile_event read-only

Decompile an event by name and return the full C# event declaration with its add/remove accessor bodies. A shorthand for the IL-prefixed path through decompile_method (add_X, remove_X) — use it when you have the event name and want everything about it.

assembly required
string — path to the assembly, inside an allow-root.
typeName required
string — fully qualified type name.
eventName required
string — the unprefixed event name, e.g. Changed.

Returns. A header comment naming the event and its origin, followed by the decompiled C# event declaration.

Errors.

  • Assembly path outside the allow-roots, or the file is missing.
  • Type not found, or the event not found on the type or its base types.
  • Assembly larger than the memory budget.

See also: decompile_property, decompile_method.

decompile_method read-only

Decompile a single method to C# source — faster and more focused than decompile_type when you only need one method. Property and event accessors are reachable by their IL name (get_X, set_X, add_X, remove_X) even though find_methods hides them from generic browsing.

assembly required
string — path to the assembly, inside an allow-root.
typeName required
string — fully qualified type name.
methodName required
string — the method name (or accessor IL name).
parameterCount optional
int? — disambiguates overloads by arity.
parameterTypes optional
string[] — disambiguates same-arity overloads by type (loose matching, like find_methods).

A hint is a filter that must be satisfied, not a tie-breaker consulted only when several overloads compete: a lone candidate that does not match the hint is rejected rather than returned, so the tool never answers with a different overload than the one asked for. Because C# overload resolution spans the inheritance chain, a hint is matched at each level of the declared → base walk, so an overload declared only on a base type still resolves; the most-derived match wins, so an override resolves to the derived declaration.

Returns. A header comment carrying the resolved signature — // Type.Method(paramTypes) → ReturnType, plus an origin note when the method is inherited or an extension — followed by the decompiled C# source. The signature is included so a caller can confirm which overload came back.

Errors.

  • Assembly path outside the allow-roots, or the file is missing.
  • Type not found, or the method not found on the type, its base types, or as an extension method.
  • No overload matches the supplied hint: No overload of 'X' on Y matches …, followed by Available: listing every same-named overload found across the inheritance chain.
  • The hints do not narrow to exactly one overload — the candidates are listed.
  • parameterCount contradicts parameterTypes.Length.
  • Assembly larger than the memory budget.

See also: decompile_type, analyze.

decompile_property read-only

Decompile a property by name and return the full C# property declaration with its accessor bodies. A shorthand for the IL-prefixed path through decompile_method (get_X, set_X). For indexer overloads, use decompile_method on get_Item / set_Item with parameterTypes.

assembly required
string — path to the assembly, inside an allow-root.
typeName required
string — fully qualified type name.
propertyName required
string — the unprefixed property name, e.g. Length.

Returns. A header comment naming the property and its origin, followed by the decompiled C# property declaration.

Errors.

  • Assembly path outside the allow-roots, or the file is missing.
  • Type not found, or the property not found on the type or its base types.
  • The name matches more than one property (an indexer with multiple overloads) — the candidates are listed.
  • Assembly larger than the memory budget.

See also: decompile_event, decompile_method.

decompile_type read-only

Decompile a type to full C# source — method bodies, internal logic, the whole declaration. Reach for it when a summary or a single method isn't enough.

assembly required
string — path to the assembly, inside an allow-root.
typeName required
string — fully qualified type name.

Returns. The full decompiled C# source of the type.

Errors.

  • Assembly path outside the allow-roots, or the file is missing.
  • Type not found.
  • Assembly larger than the memory budget.

See also: summarize_type, decompile_method.

Comparison

compare_method read-only

Compare a single method across two assemblies and emit each body labeled by source. Choose the body format: decompiled C# (the default) or normalized IL — the same IL form list_changed_types and compare_type use to decide body equality. When the two bodies are identical, the tool emits a single copy with a note instead of duplicating the text.

assemblyA required
string — path to the first assembly, inside an allow-root.
assemblyB required
string — path to the second assembly, inside an allow-root.
typeName required
string — fully qualified type name.
methodName required
string — the method name.
format optional
string — csharp (default) or il.
parameterCount optional
int? — disambiguates overloads by arity.
parameterTypes optional
string[] — disambiguates same-arity overloads by type.

Returns. When the bodies match, a single copy under an "identical in both assemblies" note. When they differ, two blocks labeled by source path.

Errors.

  • Either assembly path outside the allow-roots, or a file is missing.
  • Type or method not found in either assembly, or an ambiguous overload (candidates listed).
  • format is neither csharp nor il.
  • Either assembly larger than the memory budget.

See also: compare_type, decompile_method.

compare_type read-only

Compare one type across two assemblies — added and removed members, plus a body-changed flag per method. No C# decompilation is invoked; method-body equality uses normalized IL. Output marks added members with +, removed with -, and same-signature bodies that changed with ~.

assemblyA required
string — path to the first assembly, inside an allow-root.
assemblyB required
string — path to the second assembly, inside an allow-root.
typeName required
string — fully qualified type name.

Returns. A header with the change count and one line per member change, or <type> is identical in both assemblies. when nothing differs. A type present in only one assembly is reported as present-only-in-A or present-only-in-B with its members listed.

Errors.

  • Either assembly path outside the allow-roots, or a file is missing.
  • The type is missing from both assemblies.
  • Either assembly larger than the memory budget.

See also: list_changed_types, compare_method.

list_changed_types read-only

Enumerate the types that differ between two assemblies — added, removed, or changed (metadata, members, or method bodies). A pure metadata and normalized-IL walk; the C# decompiler is never invoked. Members are matched by name plus parameter and return types, so any signature change surfaces as a remove-plus-add. By default it hides the same compiler-generated noise as list_types, so a source-generator file whose hash drifts between builds doesn't dominate the output.

assemblyA required
string — path to the first assembly, inside an allow-root.
assemblyB required
string — path to the second assembly, inside an allow-root.
namespaceFilter optional
string — restrict the walk to one namespace; omit to scan the whole module.
excludeCompilerGenerated optional
bool — drop compiler-emitted types; default true.

Returns. A change count followed by one line per changed type — Added, Removed, or Changed [metadata,members,bodies] — sorted by name. No type changes detected. when the two assemblies match.

Errors.

  • Either assembly path outside the allow-roots, or a file is missing.
  • Either assembly larger than the memory budget.

See also: compare_type, compare_method.

Troubleshooting

  • No allowed roots configured. The server cannot load any assemblies. — the server was started without any --allow-root flags. Add at least one in your .mcp.json args.
  • "outside allowed roots" / path rejection — the assembly path is not inside any configured root, or it contains a .. traversal segment, or it is a symbolic link whose real target escapes the root. Point at a file genuinely inside an allow-root.
  • "exceeds … budget" — the assembly alone is larger than the total memory budget. Raise it with --max-total-size <MB>.
  • Type not found / Method not found — the fully qualified name is wrong or the member lives elsewhere. Use search_types or list_types to find the exact name, and list_members or find_methods for members.
  • "has N matching overloads" / ambiguity — narrow a method with parameterCount or parameterTypes; for an indexer, use decompile_method on get_Item / set_Item.
  • No overload of '…' matches … — a parameterCount / parameterTypes hint is a filter that must be satisfied, so a signature that does not exist is reported rather than silently answered with a different overload. The Available: list names every same-named overload found across the inheritance chain — re-query with one of those signatures. An accurate "no such overload" is often itself the answer (for example, proving a type does not override a method).
  • Unknown argument '…' for tool '…'. Valid arguments: … — an argument name the tool does not declare was supplied. Unrecognized arguments are rejected rather than ignored, because a silently dropped filter would return an unfiltered result that looks like a real answer. Re-send using one of the names listed in the message.
  • Analysis kind '…' is not valid for … — the chosen analyze kind doesn't apply to that symbol category. Pick one from the valid set for the category.
  • Unknown format '…' (compare_method) — format must be csharp or il.

Appendix A: Alternative installers

For machines where winget is unavailable or locked down by policy, or where you'd rather inspect the binary before granting it execution.

PowerShell one-liner

irm https://raw.githubusercontent.com/tadis174/ILens/main/install.ps1 | iex

Installs to %LOCALAPPDATA%\Programs\ILens\ and adds that directory to your user PATH. No admin elevation needed.

Manual ZIP

Download ILens-windows-x64.zip from the Releases page, extract it anywhere, and either add the directory to PATH yourself or reference the binary by its full path in .mcp.json's command field.

Appendix B: Updating and uninstalling

winget (recommended): winget upgrade Tadis.ILens to update; winget uninstall Tadis.ILens to remove.

PowerShell one-liner: re-run irm https://raw.githubusercontent.com/tadis174/ILens/main/install.ps1 | iex to update — the script overwrites the install directory in place and stops any running ILens processes first; uninstall with irm https://raw.githubusercontent.com/tadis174/ILens/main/uninstall.ps1 | iex.

Manual ZIP: no automatic update — re-download ILens-windows-x64.zip and re-extract on each new release; delete the extracted folder to uninstall (and remove the PATH entry if you added one).

Appendix C: Installation troubleshooting

Antivirus / Windows Defender quarantine. Self-contained .NET binaries are sometimes false-positive-flagged on first sight. Check quarantine and restore ILens.exe, or add an exception for the install directory (%LOCALAPPDATA%\Microsoft\WinGet\Packages\Tadis.ILens_*\ for winget, %LOCALAPPDATA%\Programs\ILens\ for the PowerShell script) before re-running the installer.

SmartScreen "Windows protected your PC". Browser-downloaded ZIPs carry Mark-of-the-Web, which triggers this dialog; the winget and PowerShell paths don't, so they bypass it. For a manual browser download, click "More info → Run anyway".

winget upgrade fails with remove: Access is denied: "...\ILens.exe". A running ILens MCP server (a Claude Code session, Claude Desktop, or another AI client that registered ILens) holds an exclusive lock on the binary winget is trying to replace. Close every AI client with ILens registered and re-run the upgrade. The PowerShell install.ps1 path handles this automatically by stopping running ILens processes before extraction; winget's portable installer type has no pre-install hook where an equivalent step could run.

Appendix D: claude mcp add CLI

A programmatic alternative to editing .mcp.json by hand:

claude mcp add ilens ilens -- --allow-root "C:\path\to\dlls"

The "double ilens" is intentional — the first is the MCP server alias (it matches the JSON key in .mcp.json), the second is the binary on PATH after install. The -- separator before --allow-root is required so claude mcp add does not consume --allow-root as one of its own options.
