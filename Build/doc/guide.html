Why ILens

AI agents inspecting a compiled .NET assembly typically fall back to ildasm (IL dump) or ilspycmd (full C# decompile) shelled out via Bash. Each invocation dumps an entire file as text, which then stays in the agent's context as input tokens on every subsequent turn — quickly thousands of tokens spent inspecting a single class.

Illustrative figures against a reference assembly of roughly 2 MB with ~500 public types. Numbers are order-of-magnitude estimates, not measured benchmarks:

Task Baseline Baseline tokens ILens tool ILens tokens
List every public type ilspycmd full-file ~10⁵ list_types ~10³
See the API surface of one mid-sized class ilspycmd full-file ~10⁵ summarize_type ~10²–10³
Find which type exposes a method ildasm + grep ~10⁵ search_types / find_methods ~10²

ILens turns assembly inspection into bounded, targeted lookups instead of full-file dumps — which is what makes it cheap enough to leave registered as an always-available tool.

Overview and scope

ILens is an MCP server. It speaks the Model Context Protocol over stdio and exposes read-only tools in three categories — discovery, inspection, and decompilation — that an agent calls to inspect a .NET assembly. Its trust posture is narrow: every tool is read-only, assemblies load only from directories you explicitly allow with --allow-root, it makes no network calls, and it ships as one self-contained binary. Per-tool detail is in the Tool reference below.

A note on scope: ILens is built for inspecting C# assemblies, and its output is C#. The metadata-driven tools — list_types, search_types, list_members, find_methods, and analyze — read language-agnostic metadata and work on an assembly produced by any .NET language. The decompiling tools — decompile_type, decompile_method, and summarize_type — always emit C#; run against an assembly compiled from F#, VB.NET, or C++/CLI they still work, but constructs that have no C# equivalent may render unfaithfully.

Built on ILSpy

ILens would be nothing without ILSpy. The decompiler, the analyzer, the type system that lets ILens speak about a .NET assembly in C# terms at all — none of that is ILens's. It belongs to the ILSpy team. The two libraries ILens links are ICSharpCode.Decompiler (the decompiler proper) and ICSharpCode.ILSpyX (the analyzer infrastructure). They represent more than a decade of careful work; this project is, candidly, a thin MCP shim on top.

That work is MIT-licensed, which is the only reason ILens can exist. If ILens is useful to you, please consider giving ILSpy a star. They earned it.

To be clear: bug reports and feature requests about ILens belong on the ILens issue tracker, not ILSpy's. Please don't take downstream problems to the upstream maintainers — they have enough work of their own.

Installation

System requirements: Windows 10/11, x64. The binary is self-contained — no separate .NET runtime install required.

Recommended: PowerShell

irm https://raw.githubusercontent.com/tadis174/ILens/main/install.ps1 | iex

Downloads the latest release ZIP, extracts to %LOCALAPPDATA%\Programs\ILens\, and adds that directory to your user-level PATH. No admin elevation needed. Re-running the same one-liner overwrites the install in place — that doubles as the upgrade path.

Alternative: winget

winget install Tadis.ILens

ILens is currently pending Microsoft Store review. If winget cannot find the package yet, prefer the PowerShell one-liner above until winget finds it.

PATH refresh in the current shell

The installer adds the install directory to user-level PATH. User-level PATH only takes effect in new shells, so ilens will not be invocable in the same window where you ran the install command without a refresh. Either open a new terminal, or paste this one-liner into the current shell:

$env:PATH = "$env:LOCALAPPDATA\Programs\ILens;$env:PATH"

Updating

  • Script-installed: re-run the PowerShell one-liner. The script wipes and replaces the install directory in place.
  • Winget-installed: winget upgrade Tadis.ILens.

Uninstall

  • Script-installed: 
    irm https://raw.githubusercontent.com/tadis174/ILens/main/uninstall.ps1 | iex
    Removes the install directory and strips the PATH entry. Does not touch winget-installed copies.
  • Winget-installed: winget uninstall Tadis.ILens.
Manual ZIP installation (advanced)

For air-gapped environments or when you want to audit the binary before granting execution, the release ZIP is always attached to each GitHub Release as ILens-windows-x64.zip. Download, extract anywhere, then either add the directory to PATH manually (setx PATH "%PATH%;C:\path\to\ILens", requires a new shell), or invoke the binary by its full path in .mcp.json's command field.

The ZIP contains ILens.exe, LICENSE, README.md, this guide.html, THIRD-PARTY-NOTICES.txt, and the per-source attribution files under third-party-licenses/.

Troubleshooting installation

Antivirus or Windows Defender quarantines ILens.exe. Self-contained .NET binaries bundle the entire runtime and are sometimes false-positive-flagged on first sight. Workaround: check the antivirus quarantine and restore the file, or add an exception for %LOCALAPPDATA%\Programs\ILens\ before re-running the installer. The install script detects a missing binary after extraction and points you at this section.

SmartScreen shows a "Windows protected your PC" dialog. This only fires on manual browser downloads of the ZIP — the script and winget install paths do not carry Mark-of-the-Web and do not trigger SmartScreen. If you do see the dialog on a manual download, click "More info → Run anyway".

Integrating with Claude Code

Add an entry to .mcp.json in your project root. The installer adds ilens to your PATH, so the command field references the binary by name — no full path needed:

{
  "mcpServers": {
    "ilens": {
      "command": "ilens",
      "args": [
        "--allow-root", "C:\\path\\to\\dlls"
      ]
    }
  }
}

Heads up: Claude Code only registers MCP servers at session start. Editing .mcp.json inside a running session does not pick up the new server in that session — start a new session (menu: "New session"). Restarting just the IDE or CLI window is not sufficient; the same conversation persists across the restart.

Each --allow-root flag adds a directory tree from which assemblies may be loaded. Without any --allow-root flags, the server cannot load any assemblies. Tool calls supply the assembly path per request; the server validates that the path is inside one of the configured roots, rejects path traversal (..), resolves symbolic links and junctions before re-checking containment, and bounds total memory with an aggregate budget (default 200 MB, raised with --max-total-size <MB>).

For the equivalent claude mcp add CLI command see Appendix A; for Claude Desktop see Appendix B.

Project-level guidance

Registering the server makes the ILens tools available to Claude. What makes Claude actively prefer them over reaching for ildasm / ilspycmd via Bash, reading assembly files directly, or web-searching for source is a short hint in the consuming project's CLAUDE.md. Without that hint, the model defaults to general-purpose tools.

Drop the following block into your project's CLAUDE.md, replacing <allow-root> with the directory configured in your .mcp.json:

## Inspecting .NET assemblies

Assemblies under <allow-root> are reachable through the `ilens` MCP server.
Prefer ILens tools over running `ildasm` / `ilspycmd` via Bash, reading assembly
files directly, or web-searching for source.

- Discovery: `search_types` (substring match), `list_types` (whole namespace),
  `find_methods` (signature search).
- Reading: `summarize_type` (public surface, no bodies), `list_members`
  (filtered surface), `decompile_type` (full C#), `decompile_method` (single
  method body).
- Cross-references: `analyze` with `kind` set to one of `UsedBy`,
  `InstantiatedBy`, `ExposedBy`, `ExtensionMethods`, `AppliedTo`,
  `OverriddenBy`, `ImplementedBy`, `Uses`, `Implements`, `ReadBy`,
  `AssignedBy`. Valid kinds depend on the symbol category.

Per-line walkthrough

  • The first paragraph is the load-bearing prefer-MCP rule. Without it, models default to Bash.
  • The discovery bullet routes "I don't know the full name" tasks to the right tool: a partial name goes to search_types, a known namespace goes to list_types, a method shape goes to find_methods.
  • The reading bullet escalates from cheapest to most expensive: summarize_type first, list_members when only part of the surface is needed, decompile_method for one method body, decompile_type only when full source is required.
  • The analyze bullet enumerates the kind enum so the model picks values the schema accepts — using one that does not apply to the symbol category produces an error like Analysis kind 'ReadBy' is not valid for Method.

Security model

  • --allow-root flags are mandatory at startup — without at least one root, the server cannot load any assemblies.
  • Every assembly path supplied by a tool call is validated against the configured roots; symbolic links and junctions are resolved to their real target first, so a link planted inside a root cannot point the loader outside it.
  • Path-traversal segments (raw ..) are rejected as defense-in-depth before normalization.
  • Total memory is bounded by an aggregate budget (default 200 MB, set with --max-total-size <MB>): a load past the budget evicts least-recently-used assemblies, and a single assembly larger than the whole budget is refused.
  • All MCP tools are read-only — no writes to assemblies, no shell-out, no network calls.
  • The server speaks stdio only; it does not open a network port.
  • The allow-root list bounds which target assemblies can be inspected — it is not the boundary of every file ILens opens. Decompilation also reads the target's dependency assemblies (sibling assemblies in its directory, and .NET framework/runtime assemblies) as type-resolution context.

Tool reference

Every tool is read-only. Every tool that takes an assembly parameter rejects paths that are empty, contain .., fall outside the configured --allow-root directories, resolve through a symbolic link to outside the roots, or don't exist on disk — and a load that would exceed the aggregate memory budget is refused. Those path and budget errors are not repeated under each tool's "Errors" list — only tool-specific errors are listed there.

Discovery

find_methods read-only

Search the assembly for methods matching a signature. Filters can be combined: name pattern, return type, parameter types, parameter count, declaring namespace, declaring-type pattern, and accessibility. Constructors and property/event accessors are excluded; operator methods (op_*) are included. Type patterns match by short name or full name; generics are erased at the top level (List matches List<T> for any T); Nullable<T> is unwrapped (int matches both int and int?); arrays use [] suffix. Matching is exact — no inheritance walk — so use analyze with UsedBy / Uses for assignability-aware exploration.

Parameters

assembly required string
Path to the .NET assembly to inspect (must be under an allowed root).
namePattern optional string
Case-insensitive substring filter on method name.
returns optional string
Return-type pattern (e.g., bool, IEnumerable, String).
parameterTypes optional string[]
Ordered list of parameter-type patterns. The method must have exactly this many parameters, each matching the pattern at its position.
parameterCount optional int?
Exact parameter count. If parameterTypes is also set, the two must agree.
declaringNamespace optional string
Exact declaring namespace, e.g. System.IO or System.Collections.Generic.
declaringTypePattern optional string
Case-insensitive substring filter on declaring type's short name.
accessibility optional AccessibilityFilter
Accessibility filter. Default: PublicProtected.
limit optional int?
Cap on result lines. Default: 50.

Returns. A header line stating the match count (and a "showing N" note if truncated), followed by one signature per line in the form static? FullyQualifiedType.Name(params) → returnType. Results are sorted by declaring type then method name. Empty result returns (no methods match).

Errors

  • parameterCount (N) contradicts parameterTypes.Length (M) when both are set and disagree.

See also: search_types (find types, not methods); analyze with Uses / UsedBy for assignability-aware references.

list_allowed_roots read-only

List the directories from which assemblies can be loaded. Any assembly parameter passed to other tools must point to a file inside one of these.

Parameters. None.

Returns. Newline-separated list of configured root directories. If no roots are configured, returns No allowed roots configured. The server cannot load any assemblies.

Errors. None — this tool always succeeds.

See also: use this when planning an assembly argument for any other tool.

list_types read-only

List all types in a namespace, sorted alphabetically by short name. Returns fully qualified names so they feed directly into other tools.

Parameters

assembly required string
Path to the .NET assembly to inspect (must be under an allowed root).
namespaceName required string
Namespace to list types from, e.g. System.IO or System.Collections.Generic.

Returns. {count} types: followed by one fully qualified name per line. An empty result returns No types found in namespace '{namespaceName}'.

Errors. No tool-specific errors. The namespace not existing returns the "no types found" message, not an error.

See also: search_types for substring search across namespaces.

search_types read-only

Search for types by name pattern. Matching is a case-insensitive substring applied to each type's short name; the namespace is not part of the match. Results are returned as fully qualified names so they feed directly into other tools. Capped at 50 matches.

Parameters

assembly required string
Path to the .NET assembly to inspect (must be under an allowed root).
pattern required string
Search pattern matched as a case-insensitive substring against each type's short name. E.g. Stream finds MemoryStream, FileStream, BufferedStream, etc.

Returns. {count} matches: followed by one fully qualified name per line, with a trailing ... (truncated, more than 50 matches) line when the cap was reached. Empty result returns No types matching '{pattern}'.

Errors. No tool-specific errors. An unmatched pattern returns the "no types matching" message, not an error.

See also: list_types when you know the namespace; find_methods when you're looking for a method shape rather than a type name.

Inspection

analyze read-only

Run cross-reference analysis on a type or member. Omit memberName to analyze the type itself. Valid kind values depend on the symbol category:

TypeUsedBy, InstantiatedBy, ExposedBy, ExtensionMethods, AppliedTo
MethodUsedBy, OverriddenBy, ImplementedBy, Uses, Implements
PropertyOverriddenBy, ImplementedBy
FieldReadBy, AssignedBy
EventOverriddenBy, ImplementedBy

AppliedTo requires an attribute-derived type. On a non-attribute type it returns an error rather than an empty result — an empty result would be indistinguishable from "this attribute is applied nowhere".

Parameters

assembly required string
Path to the .NET assembly to inspect (must be under an allowed root).
typeName required string
Fully qualified type name, e.g. System.String or System.IO.File.
kind required AnalysisKind
Analysis kind from the table above.
memberName optional string
Member name. Omit (or pass empty string) to analyze the type itself. Resolution order is method → property → field → event.
parameterCount optional int?
Method-overload disambiguator (only relevant when memberName resolves to a method). If parameterTypes is also given, the two must agree.
parameterTypes optional string[]
Ordered parameter-type patterns to disambiguate same-arity method overloads (only relevant when memberName resolves to a method). Same loose matching as find_methods.
limit optional int?
Cap on result lines. Default: 50.

Returns. {kind header} — {symbol display} {origin}: followed by a formatted symbol list. The origin annotation is added when the resolved member came from a base type ([inherited from ...]) or an extension method ([extension method on ...]).

Errors

  • Type not found: {typeName}. when the type does not exist in the assembly. Use search_types to discover the correct fully qualified name.
  • Member '{memberName}' not found on {type}, its base types, or as an extension method.
  • Member '{memberName}' on {type} is ambiguous — it exists as more than one member kind ... when a name resolves to several member kinds at once (an obfuscated-assembly case; C# itself forbids this).
  • '{methodName}' on {context} has N matching overloads; specify parameterCount or parameterTypes to disambiguate: ... when the member name resolves to multiple methods.
  • No overload of '{methodName}' on {context} matches {filter}. Available: ... when parameterCount or parameterTypes doesn't match any overload.
  • Analysis kind '{kind}' is not valid for {category}. Valid kinds for {category}: ... when kind doesn't apply to the resolved symbol category.
  • Analysis kind 'AppliedTo' requires an attribute type; {type} does not derive from System.Attribute. when kind is AppliedTo on a non-attribute type.

See also: find_methods for shape-based discovery; decompile_method when you need a method body, not its call graph.

list_members read-only

List members of a type, grouped by kind (Methods / Properties / Fields / Events). Returns one signature per line — no method bodies, no XML doc. Filter by member kind, accessibility, and case-insensitive name pattern. Cheaper than summarize_type when you only need part of the API surface.

With includeInherited: true, walks the base-class chain (stops at System.Object) and includes inherited members with a [from BaseType] annotation; overrides hide the base member, deduplicated by signature.

Parameters

assembly required string
Path to the .NET assembly to inspect (must be under an allowed root).
typeName required string
Fully qualified type name, e.g. System.String or System.IO.File.
kinds optional MemberKind[]
Member kinds to include. Omit to include all four (Method, Property, Field, Event).
accessibility optional AccessibilityFilter
Accessibility filter. Default: PublicProtected.
namePattern optional string
Case-insensitive substring filter on member name.
includeInherited optional bool
Include members declared on base types (stops at System.Object). Default: false.
limit optional int?
Cap on total result lines across all kinds. Default: 100.

Returns. Type header followed by one {Kind} (N): section per requested kind, with one indented signature per line. If includeInherited is on, members from base types are annotated [from BaseType]. A trailing ... (truncated, N more members; raise limit to see all) appears when the limit cuts the output. When nothing matches the filter, returns {type}: no members match the filter.

Errors

  • Type not found: {typeName}.

See also: summarize_type for the full public surface in C# form; find_methods for cross-type method search.

summarize_type read-only

Get the public and protected API surface of a type — signatures only, no method bodies. Use this for quick lookups of available members, fields, and properties.

Output is C# source with non-public members removed and method bodies replaced by a semicolon. Interface members (which have no explicit access modifiers) are kept regardless.

Parameters

assembly required string
Path to the .NET assembly to inspect (must be under an allowed root).
typeName required string
Fully qualified type name, e.g. System.String or System.IO.File.

Returns. C# source for the type with non-public members stripped and bodies elided.

Errors

  • Type not found: {typeName}.

See also: list_members when only part of the surface is needed; decompile_type for the full source including private members and method bodies.

Decompilation

decompile_method read-only

Decompile a single method to C# source code. Faster and more focused than decompile_type when you only need one method.

The output is prefixed with a one-line C# comment naming the method (and, when the method came from a base type or an extension class, the origin).

Parameters

assembly required string
Path to the .NET assembly to inspect (must be under an allowed root).
typeName required string
Fully qualified type name, e.g. System.IO.File.
methodName required string
Method name, e.g. ReadAllText.
parameterCount optional int?
Number of parameters, to disambiguate overloads. If parameterTypes is also given, the two must agree.
parameterTypes optional string[]
Ordered parameter-type patterns to disambiguate same-arity overloads, e.g. ['String'] or ['Int32','Boolean']. Same loose matching as find_methods: short or full name, generics erased, [] for arrays.

Returns. A C# comment header followed by the decompiled method body.

Errors

  • Type not found: {typeName}.
  • Method '{methodName}' not found on {type}, its base types, or as an extension method.
  • '{methodName}' on {context} has N matching overloads; specify parameterCount or parameterTypes to disambiguate: ...
  • No overload of '{methodName}' on {context} matches {filter}. Available: ... — {filter} echoes the count or type list you supplied.

See also: decompile_type for full-type decompilation; analyze with Uses / UsedBy for the method's call graph.

decompile_type read-only

Decompile a type to full C# source code. Use this to understand implementation details, method bodies, and internal logic. The most expensive of the inspection tools; prefer summarize_type, list_members, or decompile_method when full source is not needed.

Parameters

assembly required string
Path to the .NET assembly to inspect (must be under an allowed root).
typeName required string
Fully qualified type name, e.g. System.String or System.IO.File.

Returns. Full C# decompilation of the type, including private members and method bodies.

Errors

  • Type not found: {typeName}.

See also: summarize_type for signatures-only; decompile_method for a single method.

Troubleshooting

Error messages surface verbatim through the MCP transport, wrapped in Error: ArgumentException: {message} by the tool-error filter. The message tells you what went wrong; this table maps the common ones to likely causes.

Error messageLikely cause
No allowed roots configured. The server cannot load any assemblies. Server was launched without any --allow-root flag. Add at least one to .mcp.json's args and restart the Claude Code session.
Assembly path is empty. The assembly parameter was empty or whitespace.
Path contains '..' which is not allowed: ... The assembly path had a raw .. segment. Rewrite the path without parent-directory traversal.
Path is not under any allowed root: ... The assembly path resolves outside every configured --allow-root directory. Either add a new root or use a path that's already covered. Call list_allowed_roots to see what's currently configured.
Path resolves (via a symbolic link or junction) to a location outside any allowed root: ... The path itself sits inside a root, but a symbolic link or junction along it points outside every root. ILens resolves links to their real target before the containment check.
Assembly file does not exist: ... The path resolved correctly but no file is there. Check the path.
Assembly is N MB, which exceeds the M MB total memory budget on its own: ... The assembly alone is larger than the whole memory budget, so it can never fit. Raise the budget with --max-total-size <MB> in .mcp.json's args (default is 200 MB).
Type not found: ... The fully qualified type name doesn't exist in the assembly. Use search_types with a substring to find the correct name. Nested types use + in their canonical form; ILens accepts both + and dotted variants.
Member '...' not found on ... No method, property, field, or event by that name on the type, its base types, or as an extension method. Use list_members or summarize_type to see what's available.
'...' on ... has N matching overloads; specify parameterCount or parameterTypes to disambiguate: ... Multiple methods share that name. Pass parameterCount, or parameterTypes for same-arity overloads, using one of the candidates listed in the message.
No overload of '...' on ... matches {filter}. Available: ... The parameterCount or parameterTypes you supplied doesn't match any overload. The message lists what's available.
Analysis kind '...' is not valid for {category}. The kind doesn't apply to the resolved symbol category. The message lists valid kinds for that category. The kind/category table is in the analyze reference above.
parameterCount (N) contradicts parameterTypes.Length (M) A tool was called with both parameterCount and parameterTypes set to inconsistent values. Drop one or align them.

Appendix A: claude mcp add CLI

For users who'd rather not edit .mcp.json by hand, Claude Code's CLI can register the server directly:

claude mcp add ilens ilens -- --allow-root "C:\path\to\dlls"

The "double ilens" is intentional — the first is the MCP server alias (matches the JSON key in .mcp.json); the second is the binary on PATH after install. The -- separator before --allow-root is required so claude mcp add does not consume --allow-root as one of its own options.
