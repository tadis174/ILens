Why ILens

An AI agent that needs to look inside a compiled .dll typically falls back to ildasm (IL dump) or ilspycmd (full C# decompile), shelled out via Bash. Both tools dump an entire file as text. That text becomes part of the agent's context and is paid for again as input tokens on every subsequent turn — so a single careless lookup quickly accumulates thousands of tokens spent inspecting one class.

Order-of-magnitude cost for the same questions, against a reference assembly of roughly 2 MB and ~500 public types. Numbers are illustrative, not measured; the point is the shape, not the precision.

Taskildasm / ilspycmdILens equivalentILens cost
List every public type ~105 tokens list_types per namespace ~102
API surface of one mid-sized class ~105 summarize_type 102–103
Find which type exposes a method ~105 search_types or find_methods 102–103

ILens turns assembly inspection into bounded, targeted lookups instead of full-file dumps — which is what makes it cheap enough to leave registered as an always-available tool.

Overview

ILens is an MCP server that speaks JSON-RPC over stdio and exposes nine tools across three categories: discovery (find types and methods by name or signature), inspection (summarize an API surface, list members, run cross-reference analysis), and decompilation (read the C# source of a type or a single method). Trust posture: every tool is read-only, every assembly path is validated against an explicit --allow-root allow-list, no shell-out, no network. Single self-contained binary, no .NET runtime install required.

Installation

Extract the release ZIP anywhere. The binary is ILens.exe; no .NET runtime install is required (the binary is self-contained). Windows x64 only — that is the runtime identifier the publish target ships.

The bundled distribution also contains LICENSE (ILens is MIT), THIRD-PARTY-NOTICES.txt (top-level entry into the third-party-attribution archive), README.md, this guide.html, and a third-party-licenses/ directory with per-source LICENSE files and an INDEX.md mapping each NuGet package and runtime component to its upstream source.

Integrating with Claude Code

Drop a .mcp.json file in your project root:

{
  "mcpServers": {
    "ilens": {
      "command": "C:\\path\\to\\ILens.exe",
      "args": [
        "--allow-root", "C:\\path\\to\\dlls"
      ]
    }
  }
}
Heads up: Claude Code only registers MCP servers at session start. Editing .mcp.json inside a running session will not register the new server in that session — start a new session (menu: "New session"). Restarting the IDE or CLI window alone is not sufficient; the same conversation persists across the restart.

Each --allow-root flag adds a directory tree from which assemblies may be loaded. Without any --allow-root flags, the server cannot load any assemblies. Tool calls supply the assembly path per request; the server validates that the path is inside one of the configured roots, rejects path traversal (..), and refuses files larger than 200 MB.

For the equivalent claude mcp add CLI command see Appendix A; for Claude Desktop see Appendix B.

Project-level guidance

Registering the server makes the tools available, not preferred. Without a hint in the consuming project's CLAUDE.md, Claude will keep reaching for ildasm via Bash, reading .dll files directly, or web-searching for source — exactly the expensive paths ILens replaces. Drop the block below into your project's CLAUDE.md and replace <allow-root> with the directory configured above:

## Inspecting .NET assemblies

Assemblies under `<allow-root>` are reachable through the `ilens` MCP server.
Prefer ILens tools over running `ildasm` / `ilspycmd` via Bash, reading `.dll`
files directly, or web-searching for source.

- Discovery: `search_types` (substring match), `list_types` (whole namespace),
  `find_methods` (signature search).
- Reading: `summarize_type` (public surface, no bodies), `list_members`
  (filtered surface), `decompile_type` (full C#), `decompile_method` (single
  method body).
- Cross-references: `analyze` with `kind` set to one of `UsedBy`,
  `InstantiatedBy`, `ExposedBy`, `ExtensionMethods`, `AppliedTo`,
  `OverriddenBy`, `ImplementedBy`, `Uses`, `Implements`, `ReadBy`,
  `AssignedBy`. Valid kinds depend on the symbol category.

Per-line walkthrough

  • The opening paragraph is the load-bearing prefer-MCP rule. Without it, models default to Bash.
  • The Discovery bullet routes "I don't know the full name" tasks to the right tool: a partial name goes to search_types, a known namespace to list_types, a method shape to find_methods.
  • The Reading bullet escalates from cheapest to most expensive: summarize_type first, list_members when only part of the surface is needed, decompile_method for one method body, decompile_type only when full source is required.
  • The analyze bullet enumerates the kind enum so the model picks values the schema accepts. Using one that does not apply to the symbol category produces an error like Analysis kind 'ReadBy' is not valid for Method.

Security model

  • --allow-root flags are mandatory; with no roots configured, the server refuses every load with a clear "no allowed roots" message.
  • Every request validates that the requested assembly path is inside one of the configured roots (after path normalization, with separator-bounded prefix matching).
  • Path-traversal segments (..) are rejected before normalization (defense in depth, even though normalization would resolve them).
  • Files larger than 200 MB are refused with the actual size in the error message.
  • All MCP tools are read-only — no writes to assemblies, no shell-out, no network calls.
  • The server speaks stdio only; it does not open a network port. Logging goes to stderr, leaving stdout clean for the JSON-RPC transport.

Tool reference

Every parameter named assembly is a path that must resolve to a file inside one of the configured --allow-root directories. The same path-validation errors (empty path, traversal, outside-root, missing file, size cap) can surface from any tool that takes an assembly parameter; they are listed once under Troubleshooting rather than repeated per tool.

Discovery

find_methods read-only

Search the assembly for methods matching a signature. Any combination of name pattern, return type, parameter types, parameter count, declaring namespace, declaring-type pattern, and accessibility is accepted; constructors and property/event accessors are excluded, operators (op_*) are included.

Parameters

assembly string required
Path to the .NET assembly to inspect (must be under an allowed root).
namePattern string? optional
Case-insensitive substring filter on method name.
returns string? optional
Return-type pattern. Matches by short name or full name (Pawn or Verse.Pawn). Generics are erased at the top level (List matches List<T> for any T); Nullable<T> is unwrapped (int matches int?); arrays use a trailing [].
parameterTypes string[]? optional
Ordered list of parameter-type patterns. The method must have exactly this many parameters, each matching at its position. Same matching rules as returns.
parameterCount int? optional
Exact parameter count. If parameterTypes is also set, the two must agree.
declaringNamespace string? optional
Exact declaring namespace, e.g. RimWorld or Verse.
declaringTypePattern string? optional
Case-insensitive substring filter on the declaring type's short name.
accessibility AccessibilityFilter optional
One of Public, PublicProtected (default), All.
limit int? optional
Cap on result lines. Default 50.

Returns

A header line (N matches, optionally followed by (showing M)) and one signature per match: DeclaringType.MethodName(parameters) → ReturnType, sorted by declaring type then method name. Static methods are prefixed with static. (no methods match) when nothing qualifies.

Errors

  • parameterCount (X) contradicts parameterTypes.Length (Y) — both are set but disagree.
  • Standard path-validation errors (see Troubleshooting).

See also: search_types for short-name matching; analyze with UsedBy/Uses for assignability-aware exploration.

list_allowed_roots read-only

Returns the directories the server was launched with. Any assembly argument to other tools must point to a file under one of these.

Parameters

None.

Returns

One root path per line, in the order they were configured. No allowed roots configured. The server cannot load any assemblies. when the server was launched without --allow-root flags.

Errors

None — this tool always succeeds.

See also: every other tool's assembly parameter validates against this list.

list_types read-only

List every type in a namespace, sorted alphabetically by short name. Output is fully qualified names so they can be fed directly into other tools.

Parameters

assembly string required
Path to the .NET assembly to inspect.
namespaceName string required
Exact namespace, e.g. RimWorld or Verse.

Returns

A header line N types: followed by one fully qualified name per line. No types found in namespace 'X' when the namespace contains nothing.

Errors

  • Standard path-validation errors (see Troubleshooting).

See also: search_types when you don't know which namespace to scan.

search_types read-only

Find types whose short name contains a pattern (case-insensitive substring; the namespace is not part of the match). Capped at 50 matches.

Parameters

assembly string required
Path to the .NET assembly to inspect.
pattern string required
Substring matched case-insensitively against each type's short name. Plant finds PlantProperties, PlantUtility, etc.

Returns

A header line N matches: followed by one fully qualified name per line. When more than 50 types match, the response is truncated and ends with ... (truncated, more than 50 matches). No types matching 'pattern' when nothing qualifies.

Errors

  • Standard path-validation errors (see Troubleshooting).

See also: list_types for whole-namespace listing; find_methods for method-shape search.

Inspection

analyze read-only

Run cross-reference analysis on a type or member. Each kind applies only to certain symbol categories; passing the wrong combination produces a clear error rather than empty results.

Valid kinds by symbol category

SymbolKinds
TypeUsedBy, InstantiatedBy, ExposedBy, ExtensionMethods, AppliedTo
MethodUsedBy, OverriddenBy, ImplementedBy, Uses, Implements
PropertyOverriddenBy, ImplementedBy
FieldReadBy, AssignedBy
EventOverriddenBy, ImplementedBy

AppliedTo is meaningful only on Attribute-derived types; on a non-attribute type the underlying analyzer's Show(symbol) returns false and the result is empty (not an error).

Parameters

assembly string required
Path to the .NET assembly to inspect.
typeName string required
Fully qualified type name, e.g. RimWorld.PlantProperties.
kind AnalysisKind required
One of the values in the table above.
memberName string? optional
Member name. Omit (or pass empty string) to analyze the type itself; otherwise the resolver tries method → property → field → event in turn.
parameterCount int? optional
Method-overload disambiguator. Used only when memberName resolves to a method with multiple overloads.
limit int? optional
Cap on result lines. Default 50.

Returns

A header line in the form <Header> — <Symbol> [origin]: (origin appears for inherited or extension members), followed by one symbol per line up to the limit.

Errors

  • Analysis kind 'X' is not valid for <Category>. Valid kinds for <Category>: … — the chosen kind doesn't apply to the resolved symbol's category.
  • Type not found: <name> — typeName doesn't resolve.
  • Member '<name>' not found on <type>, its base types, or as an extension method — memberName doesn't resolve.
  • '<name>' on <type> has N overloads. Specify parameterCount to disambiguate: … — ambiguous method overload.
  • No overload of '<name>' on <type> with N parameters. Available: … — parameterCount doesn't match any overload.
  • Standard path-validation errors (see Troubleshooting).

See also: summarize_type for the API surface; decompile_method to read a method body after locating its callers via UsedBy.

list_members read-only

List members of a type, grouped by kind (Methods, Properties, Fields, Events). One signature per line — no method bodies, no XML doc. Cheaper than summarize_type when you only need part of the API surface or want inherited members included.

Parameters

assembly string required
Path to the .NET assembly to inspect.
typeName string required
Fully qualified type name, e.g. RimWorld.PlantProperties.
kinds MemberKind[]? optional
Subset of Method, Property, Field, Event. Omit (or pass empty) to include all four.
accessibility AccessibilityFilter optional
Public, PublicProtected (default), or All.
namePattern string? optional
Case-insensitive substring filter on member name.
includeInherited bool optional
Include members declared on base types (stops at System.Object). Inherited members carry an [from <BaseType>] annotation; an override hides the base. Default false.
limit int? optional
Cap on total result lines across all kinds. Default 100.

Returns

The fully qualified type name (with (with inherited) appended when applicable), then a section per non-empty kind: Methods (N): / Properties (N): / Fields (N): / Events (N):, each followed by one indented signature per member. When the limit truncates output, the last line is ... (truncated, M more members; raise limit to see all). <Type>: no members match the filter. when nothing qualifies.

Errors

  • Type not found: <name> — typeName doesn't resolve.
  • Standard path-validation errors (see Troubleshooting).

See also: summarize_type for the full public/protected surface as C# (with type signature, base list, attributes); find_methods to search across the whole assembly.

summarize_type read-only

Render the public and protected API surface of a type as C# — class signature, base list, attributes, member declarations, but no method bodies. The output is the decompiled syntax tree with non-public members removed and bodies replaced with ;. Quick when you want the shape of a type without the implementation.

Parameters

assembly string required
Path to the .NET assembly to inspect.
typeName string required
Fully qualified type name, e.g. RimWorld.PlantProperties.

Returns

A C# string with the type's declaration, public/protected members (operators and indexers included; destructors excluded), and stripped bodies. Interface members are kept regardless of explicit modifier (interfaces don't carry an explicit public in C# but are implicitly public).

Errors

  • Type not found: <name> — typeName doesn't resolve.
  • Standard path-validation errors (see Troubleshooting).

See also: list_members for filtered or inherited surface; decompile_type when you actually need the bodies.

Decompilation

decompile_method read-only

Decompile a single method to C#. Faster and tokens-cheaper than decompile_type when you only need one method body.

Parameters

assembly string required
Path to the .NET assembly to inspect.
typeName string required
Fully qualified type name, e.g. RimWorld.MainTabWindow_Research.
methodName string required
Method name, e.g. ListProjects.
parameterCount int? optional
Number of parameters, used to disambiguate overloads.

Returns

A header comment (// <Type>.<Method>, with origin annotation when the method is inherited or an extension) followed by the decompiled C# source.

Errors

  • Type not found: <name> — typeName doesn't resolve.
  • Method '<name>' not found on <type>, its base types, or as an extension method — methodName doesn't resolve.
  • '<name>' on <type> has N overloads. Specify parameterCount to disambiguate: … — ambiguous method overload.
  • No overload of '<name>' on <type> with N parameters. Available: … — parameterCount doesn't match any overload.
  • Standard path-validation errors (see Troubleshooting).

See also: analyze with UsedBy to find callers before reading the body; decompile_type when you need the surrounding class.

decompile_type read-only

Decompile a type to its full C# source — every member, every body. The most expensive read in the toolkit; reach for summarize_type or decompile_method first when possible.

Parameters

assembly string required
Path to the .NET assembly to inspect.
typeName string required
Fully qualified type name, e.g. RimWorld.PlantUtility or Verse.Thing.

Returns

The complete C# source of the type as decompiled by ICSharpCode.Decompiler.

Errors

  • Type not found: <name> — typeName doesn't resolve.
  • Standard path-validation errors (see Troubleshooting).

See also: summarize_type for signatures only; decompile_method for a single method.

Troubleshooting

Error message containsLikely cause
No allowed roots configured The server was launched without any --allow-root flags. Add at least one and start a new Claude Code session.
Assembly path is empty Empty or whitespace-only assembly argument.
Path contains '..' which is not allowed The requested path has a literal .. segment. Pass the resolved absolute path instead.
Path is not under any allowed root The assembly is real but lives outside every --allow-root directory. Either move the file under an existing root or relaunch with an additional --allow-root flag.
Assembly file does not exist Typo in the path, or the file was renamed/deleted after launch.
Assembly exceeds 200 MB size cap The 200 MB hard cap is exceeded. ILens does not provide a flag to raise this — split the workload to a smaller assembly if possible.
Type not found Fully qualified name didn't match. Check namespace; for nested types use Outer+Inner (or Outer.Inner, which the resolver also tries). Use search_types to discover the right name.
Method '…' not found / Member '…' not found The name doesn't exist on the type, its base types, or as an extension method. Run list_members with a namePattern to find similar names.
has N overloads. Specify parameterCount to disambiguate Multiple methods share the same name on the type. Pass parameterCount matching the intended overload.
No overload of … with N parameters parameterCount doesn't match any overload. The error message lists the available overloads.
Analysis kind 'X' is not valid for <Category> The kind doesn't apply to the resolved symbol's category. Pick from the kinds listed for that category in the analyze table.
parameterCount (X) contradicts parameterTypes.Length (Y) find_methods got both parameterCount and parameterTypes with conflicting cardinalities. Drop one or align them.

Appendix A: claude mcp add CLI

If you'd rather not edit .mcp.json by hand, the CLI has an equivalent:

claude mcp add ilens "C:\path\to\ILens.exe" --allow-root "C:\path\to\dlls"

Run inside the project directory. The same session-restart caveat applies: registration takes effect on the next new session, not the current one.

Appendix B: Claude Desktop

Claude Desktop reads its MCP server list from %APPDATA%\Claude\claude_desktop_config.json on Windows. Add an entry equivalent to the Claude Code one:

{
  "mcpServers": {
    "ilens": {
      "command": "C:\\path\\to\\ILens.exe",
      "args": [
        "--allow-root", "C:\\path\\to\\dlls"
      ]
    }
  }
}

Claude Desktop has no per-project CLAUDE.md — there's no project boundary in the desktop client. Paste the snippet from the Project-level guidance section into your Claude Desktop Project's custom instructions instead, so the prefer-MCP rule still applies in conversations that touch your assemblies.
