Why ILens

AI agents inspecting a compiled .NET assembly typically fall back to ildasm (an IL dump) or ilspycmd (a full C# decompile), shelled out through Bash. Each invocation dumps an entire file as text, which then stays in the agent's context as input tokens on every subsequent turn — quickly thousands of tokens spent inspecting a single class.

The target assembly used for the measurements below is ICSharpCode.Decompiler.dll 9.1.0.7988, about 2 MB on disk, exposing 741 public types. A single ilspycmd dump of it amounts to roughly 1,041,476 tokens.

Task ilspycmd cost ILens tool ILens cost
List the public types in a namespace 1,041,476 tokens list_types 1,712 tokens
See the API surface of one mid-sized class 1,041,476 tokens summarize_type 895 tokens
Find which types expose a given method 1,041,476 tokens find_methods 618 tokens

Measured against ICSharpCode.Decompiler.dll 9.1.0.7988 on 2026-05-14; token figures are character counts divided by 4, not a real tokenizer.

ILens turns assembly inspection into bounded, targeted lookups instead of full-file dumps — which is what makes it cheap enough to leave registered as an always-available tool.

Overview and scope

ILens is a Model Context Protocol server. It speaks JSON-RPC over stdio and exposes nine tools across three categories: discovery (list_allowed_roots, list_types, search_types, find_methods), inspection (summarize_type, list_members, analyze), and decompilation (decompile_type, decompile_method). The trust posture is narrow: every tool is read-only, the server only opens assemblies under directories passed via --allow-root, it never opens a network port, and it ships as a single self-contained Windows binary.

Scope. ILens is built for inspecting C# assemblies, and its output is C#. The metadata-driven tools (list_types, search_types, list_members, find_methods, analyze) read language-agnostic .NET metadata and work on an assembly from any source language. The decompiling tools (decompile_type, decompile_method, summarize_type) always emit C# — for an assembly compiled from F#, VB.NET, or C++/CLI they still run, but constructs without a C# equivalent may render unfaithfully.

Built on ILSpy

ILens would be nothing without ILSpy. The decompiler, the analyzer, and the type system that lets ILens speak about a .NET assembly in C# terms at all are upstream work by the ILSpy team. ILens links ICSharpCode.Decompiler for the decompiler proper and ICSharpCode.ILSpyX for the analyzer infrastructure; this project is, candidly, a thin MCP shim on top.

That work is MIT-licensed, which is the only reason ILens can exist. If ILens is useful to you, please consider giving ILSpy a star — they earned it.

To be clear: bug reports and feature requests about ILens belong on the ILens issue tracker, not ILSpy's. Please don't take downstream problems to the upstream maintainers — they shouldn't have to inherit them.

Installation

System requirements: Windows 10 or 11, x64. The binary is self-contained — no separate .NET runtime install is required.

winget install Tadis.ILens

Standard winget portable install. The package downloads the release ZIP, extracts it under %LOCALAPPDATA%\Microsoft\WinGet\Packages\Tadis.ILens_*\, and registers ilens as a command alias in %LOCALAPPDATA%\Microsoft\WinGet\Links\ — already on the user PATH from any prior winget portable use. No admin elevation needed. Update with winget upgrade Tadis.ILens; uninstall with winget uninstall Tadis.ILens.

Alternative install paths (no winget required)

For machines where winget is unavailable, locked down by policy, or where you'd rather inspect the binary before granting it execution.

PowerShell one-liner. Installs to %LOCALAPPDATA%\Programs\ILens\ and adds that directory to your user PATH. No admin elevation needed.

irm https://raw.githubusercontent.com/tadis174/ILens/main/install.ps1 | iex

Re-run the same one-liner to update; the script overwrites the install directory in place. To uninstall:

irm https://raw.githubusercontent.com/tadis174/ILens/main/uninstall.ps1 | iex

Manual ZIP. Download ILens-windows-x64.zip from the latest release, extract anywhere, then either add the directory to your PATH or reference the binary by its full path in .mcp.json's command field. No automatic update mechanism — re-download on each new release.

Troubleshooting installation

Antivirus / Windows Defender quarantine of ILens.exe. Self-contained .NET binaries are sometimes false-positive-flagged on first sight. Check quarantine and restore the file, or add an exception for the install directory (%LOCALAPPDATA%\Microsoft\WinGet\Packages\Tadis.ILens_*\ for winget, %LOCALAPPDATA%\Programs\ILens\ for the PowerShell script) before re-running the installer.

SmartScreen "Windows protected your PC" dialog on browser-downloaded ZIP installs. The winget and PowerShell paths bypass this because they don't carry Mark-of-the-Web; for manual browser downloads, click "More info → Run anyway".

Integrating with Claude Code

Add a .mcp.json file to the root of the project where you want ILens available. The command field is the literal string "ilens" — the installer adds ilens to the user PATH, so the binary is invocable by name.

{
  "mcpServers": {
    "ilens": {
      "command": "ilens",
      "args": [
        "--allow-root", "C:\\path\\to\\dlls"
      ]
    }
  }
}

Heads up — a first install needs a full restart, not just a new session. Two independent gates have to clear before a freshly-installed ilens actually launches as an MCP server in a running Claude app session.

Gate 1: PATH propagation. Windows captures a process's PATH from the registry at process start, and later registry changes do not retroactively reach already-running processes. If ilens is a brand-new entry on user PATH — true for a first-ever winget portable install (which adds %LOCALAPPDATA%\Microsoft\WinGet\Links\ to user PATH) and for any install.ps1 run (which adds %LOCALAPPDATA%\Programs\ILens\) — an already-running Claude app holds a stale environment, and every Claude Code session inside it inherits that stale environment from the parent app. Subsequent winget upgrade Tadis.ILens runs do not touch PATH and do not trigger this gate.

Gate 2: MCP-server registration. Claude Code reads .mcp.json only at session start; editing .mcp.json inside a running session does not register the new server in that session.

Recovery takes both. Fully exit and relaunch the Claude app so the new app process gets the current registry PATH, then start a new Claude Code session in the relaunched app. Existing Claude Code sessions survive a Claude app restart — the relaunched app reattaches to surviving session processes with their original environments intact — so a resumed session won't pick up either change. Only a freshly-spawned session inside the freshly-launched app clears both gates.

Practical recipe for a first install: close Claude app entirely → install via winget (or install.ps1) → relaunch Claude app → start a new Claude Code session (not a resumed one).

Each --allow-root flag adds a directory tree from which assemblies may be loaded. Without any --allow-root flags, the server cannot load any assemblies. The server validates every path supplied per request, rejects path traversal (..), resolves symbolic links and junctions before re-checking containment, and bounds total memory with an aggregate budget (default 200 MB, settable with --max-total-size <MB>).

For the equivalent claude mcp add CLI command see Appendix A; for Claude Desktop see Appendix B.

Project-level guidance

Registering the server makes the tools available; it does not make Claude actively prefer them. Without a hint in the consuming project's CLAUDE.md, the model often defaults to running dotnet or ildasm through Bash, reading assembly files directly, or web-searching for source. The following snippet closes that gap.

Drop it into your project's CLAUDE.md and replace <allow-root> with the directory configured above:

## Inspecting .NET assemblies

Assemblies under `<allow-root>` are reachable through the `ilens` MCP server.
Prefer ILens tools over running `ildasm` / `ilspycmd` via Bash, reading assembly
files directly, or web-searching for source.

- Discovery: `search_types` (substring match), `list_types` (whole namespace),
  `find_methods` (signature search).
- Reading: `summarize_type` (public surface, no bodies), `list_members`
  (filtered surface), `decompile_type` (full C#), `decompile_method` (single
  method body).
- Cross-references: `analyze` with `kind` set to one of `UsedBy`,
  `InstantiatedBy`, `ExposedBy`, `ExtensionMethods`, `AppliedTo`,
  `OverriddenBy`, `ImplementedBy`, `Uses`, `Implements`, `ReadBy`,
  `AssignedBy`. Valid kinds depend on the symbol category.

Per-line walkthrough

  • The first paragraph is the load-bearing prefer-MCP rule. Without it, the model defaults to Bash.
  • The discovery bullet routes "I don't know the full name" tasks to the right tool: a partial name goes to search_types, a known namespace goes to list_types, a method shape goes to find_methods.
  • The reading bullet escalates from cheapest to most expensive: summarize_type first, list_members when only part of the surface is needed, decompile_method for one method body, decompile_type only when full source is required.
  • The analyze bullet enumerates the kind enum so the model picks values the schema accepts — using one that does not apply to the symbol category produces an error like Analysis kind 'ReadBy' is not valid for Method.

Security model

  • --allow-root flags are mandatory: with none configured, no assembly can be loaded and every tool call fails with "No allowed roots configured. The server cannot load any assemblies."
  • Every request validates the assembly path is inside one of the configured roots — symbolic links and junctions are resolved to their real target first, so a link planted inside a root cannot point the loader outside it.
  • Path-traversal segments (..) are rejected before normalization.
  • Total memory is bounded by an aggregate budget (default 200 MB, set with --max-total-size <MB>): a load that would exceed the budget evicts least-recently-used assemblies, and a single assembly larger than the whole budget is refused.
  • All MCP tools are read-only — no writes to assemblies, no shell-out, no network calls.
  • The server speaks stdio only; it does not open a network port.
  • The allow-root bounds which target assemblies can be inspected — it is not the boundary of every file ILens opens. Decompilation also reads the target's dependency assemblies (sibling assemblies in its directory and .NET framework/runtime assemblies) as type-resolution context.

Tool reference

Discovery

find_methods read-only

Search an assembly for methods matching any combination of name pattern, return type, parameter types, parameter count, declaring namespace, declaring-type pattern, and accessibility.

Parameters

assembly required string
Path to the .NET assembly to inspect — must point to a file under one of the configured allow-roots.
namePattern optional string
Case-insensitive substring filter on method name.
returns optional string
Return-type pattern, e.g. bool, IEnumerable, String. Patterns match by short name or full name; generics are erased at the top level (List matches List<T>); Nullable<T> is unwrapped; arrays use a [] suffix.
parameterTypes optional string[]
Ordered parameter-type patterns. The method must have exactly this many parameters, each matching the pattern at its position.
parameterCount optional int?
Exact parameter count. If parameterTypes is also set, the two must agree.
declaringNamespace optional string
Exact declaring namespace, e.g. System.IO.
declaringTypePattern optional string
Case-insensitive substring filter on the declaring type's short name.
accessibility optional AccessibilityFilter
Accessibility filter. Default PublicProtected.
limit optional int?
Cap on result lines. Default 50.

Returns

A header line stating the match count (and the cap if truncated), followed by one signature per line — DeclaringType.Name(params) → ReturnType, prefixed with static when applicable. Constructors and property/event accessors are excluded; operator methods (op_*) are included. Sorted by declaring type then method name. If nothing matches, (no methods match).

Errors

  • parameterCount and parameterTypes set with different lengths.
  • Assembly path fails PathGuard validation (see Security model).
  • Assembly exceeds the total memory budget.

See also: decompile_method for a single body, analyze for callers and overrides.

list_allowed_roots read-only

List the directories from which assemblies can be loaded. The assembly parameter of every other tool must point to a file inside one of these.

Parameters

None.

Returns

One root path per line. If no roots are configured: "No allowed roots configured. The server cannot load any assemblies."

Errors

None — this tool always returns a string and never throws.

See also: every other tool, since their assembly parameter is validated against the returned list.

list_types read-only

List every type whose namespace matches exactly, returned as fully qualified names sorted alphabetically by short name.

Parameters

assembly required string
Path to the .NET assembly to inspect.
namespaceName required string
Namespace to list types from, e.g. System.IO or System.Collections.Generic.

Returns

A header line with the count, followed by one fully qualified name per line. If nothing matches: "No types found in namespace '<namespaceName>'".

Errors

  • Assembly path fails PathGuard validation.
  • Assembly exceeds the total memory budget.

See also: search_types when the namespace is unknown.

search_types read-only

Find types whose short name contains the pattern, case-insensitively. The namespace is not part of the match; results are fully qualified names that can be fed verbatim into other tools.

Parameters

assembly required string
Path to the .NET assembly to inspect.
pattern required string
Case-insensitive substring matched against each type's short name. For example, Stream finds MemoryStream, FileStream, BufferedStream, etc.

Returns

A header line with the match count, followed by one fully qualified name per line. Capped at 50 results — a ... (truncated, more than 50 matches) line is appended when the cap is hit. If nothing matches: "No types matching '<pattern>'".

Errors

  • Assembly path fails PathGuard validation.
  • Assembly exceeds the total memory budget.

See also: list_types when the namespace is known.

Inspection

analyze read-only

Run cross-reference analysis on a type or member. Omit memberName to analyze the type itself; supply it to analyze a method, property, field, or event.

Parameters

assembly required string
Path to the .NET assembly to inspect.
typeName required string
Fully qualified type name, e.g. System.String.
kind required AnalysisKind
One of UsedBy, InstantiatedBy, ExposedBy, ExtensionMethods, AppliedTo, OverriddenBy, ImplementedBy, Uses, Implements, ReadBy, AssignedBy. Valid values depend on the symbol category:
  • Type: UsedBy, InstantiatedBy, ExposedBy, ExtensionMethods, AppliedTo
  • Method: UsedBy, OverriddenBy, ImplementedBy, Uses, Implements
  • Property: OverriddenBy, ImplementedBy
  • Field: ReadBy, AssignedBy
  • Event: OverriddenBy, ImplementedBy
memberName optional string
Member name. Omit to analyze the type itself.
parameterCount optional int?
Method overload disambiguator, used only when memberName resolves to a method. If parameterTypes is also given, the two must agree.
parameterTypes optional string[]
Ordered parameter-type patterns to disambiguate same-arity overloads. Same loose matching as find_methods.
limit optional int?
Cap on result lines. Default 50.

Returns

A header naming the analyzer and the formatted symbol, followed by one reference per line. The format is delegated to ReferenceFormatter.

Errors

  • kind not valid for the resolved symbol's category: "Analysis kind '<kind>' is not valid for <category>. Valid kinds for <category>: ..."
  • kind is AppliedTo but the type does not derive from System.Attribute: "Analysis kind 'AppliedTo' requires an attribute type; ... does not derive from System.Attribute."
  • memberName does not resolve to a single member on the type, declared bases, or extensions.
  • Same-arity overload ambiguity not narrowed by parameterTypes.
  • Assembly path fails PathGuard validation.
  • Assembly exceeds the total memory budget.

See also: decompile_method to inspect a caller body once UsedBy identifies it; find_methods to discover candidates before running UsedBy.

list_members read-only

List members of a type, grouped by kind (Methods, Properties, Fields, Events), one signature per line — no method bodies, no XML doc. Cheaper than summarize_type when only part of the API surface is wanted.

Parameters

assembly required string
Path to the .NET assembly to inspect.
typeName required string
Fully qualified type name.
kinds optional MemberKind[]
Member kinds to include. Omit to include all four (Method, Property, Field, Event).
accessibility optional AccessibilityFilter
Default PublicProtected.
namePattern optional string
Case-insensitive substring filter on member name.
includeInherited optional bool
Include members declared on base types (stops at System.Object). Default false. Overrides hide inherited members with the same signature; surviving inherited members are annotated with [from <Type>].
limit optional int?
Cap on total result lines across all kinds. Default 100.

Returns

The type's full name, then a section per non-empty kind (with its count), then one signature per line. A trailing ... (truncated, N more members; raise limit to see all) appears if the cap is hit. If nothing matches: "<type>: no members match the filter."

Errors

  • Type not found.
  • Assembly path fails PathGuard validation.
  • Assembly exceeds the total memory budget.

See also: summarize_type for the unfiltered C# surface; find_methods for cross-type method search.

summarize_type read-only

The public and protected API surface of a type, rendered as a C# declaration with member signatures only — no method bodies, no XML doc.

Parameters

assembly required string
Path to the .NET assembly to inspect.
typeName required string
Fully qualified type name, e.g. System.IO.File.

Returns

A C# source fragment with the type declaration and its public/protected members, accessor and method bodies elided. Interface members (which carry no explicit modifier) are preserved.

Errors

  • Type not found.
  • Assembly path fails PathGuard validation.
  • Assembly exceeds the total memory budget.

See also: list_members for filtered or inherited views; decompile_type for the full source.

Decompilation

decompile_method read-only

Decompile a single method body to C#. Faster and more focused than decompile_type when only one method is wanted. Property and event accessors are resolvable by their IL name (get_X, set_X, add_X, remove_X) even though find_methods hides them from generic browsing.

Parameters

assembly required string
Path to the .NET assembly to inspect.
typeName required string
Fully qualified type name.
methodName required string
Method name. Use the IL accessor name (get_X, set_X, add_X, remove_X) to decompile a property or event accessor body.
parameterCount optional int?
Number of parameters, to disambiguate overloads. If parameterTypes is also given, the two must agree.
parameterTypes optional string[]
Ordered parameter-type patterns to disambiguate same-arity overloads, e.g. ['String'] or ['Int32','Boolean']. Same loose matching as find_methods.

Returns

A header comment naming the resolved method (with origin if not declared on the named type), then the C# source of the method body.

Errors

  • Method not found on the type, its base types, or its extensions.
  • Multiple overloads match — the candidates are listed for the caller to narrow.
  • parameterCount contradicts parameterTypes.Length.
  • Type not found.
  • Assembly path fails PathGuard validation.
  • Assembly exceeds the total memory budget.

See also: find_methods to discover the method name and signature; decompile_type for the whole type.

decompile_type read-only

Decompile a type to full C# source, method bodies included.

Parameters

assembly required string
Path to the .NET assembly to inspect.
typeName required string
Fully qualified type name, e.g. System.String.

Returns

The complete C# source for the type, as emitted by CSharpDecompiler.

Errors

  • Type not found.
  • Assembly path fails PathGuard validation.
  • Assembly exceeds the total memory budget.

See also: summarize_type for signatures only; decompile_method for a single body.

Troubleshooting

"No allowed roots configured. The server cannot load any assemblies."
The server started without any --allow-root flags. Add at least one to the args array in .mcp.json, then start a new Claude Code session.
"Path is not under any allowed root: ..."
The assembly path points outside every configured root. Either move the file under a configured root or add a new --allow-root covering its directory.
"Path resolves (via a symbolic link or junction) to a location outside any allowed root: ..."
The path itself is under a root, but a symbolic link or junction in it points to a target outside every root. Use the real path of the target, or place the target under an allow-root.
"Path contains '..' which is not allowed: ..."
The path includes a raw .. segment. Pass a fully resolved absolute path.
"Assembly file does not exist: ..."
The path is under an allow-root but no file is at that location. Double-check the file name and extension — ILens has no file-extension filter, but the file must exist.
"Assembly is N MB, which exceeds the 200 MB total memory budget on its own: ..."
A single assembly is larger than the entire memory budget. Raise the budget by adding "--max-total-size", "<MB>" to the args array, then start a new session.
"Analysis kind '<kind>' is not valid for <category>. Valid kinds for <category>: ..."
The kind passed to analyze does not apply to the resolved symbol. The error message names the valid set; pick one from it.
"Analysis kind 'AppliedTo' requires an attribute type; ... does not derive from System.Attribute."
AppliedTo only applies to attribute types. Pass an Attribute-derived type, or pick a different kind.
"--allow-root path does not exist: ..." / "... is a file, not a directory"
A startup-time error: one of the configured roots is missing or a file. Fix the args entry and start a new session.
New server entry in .mcp.json not showing up
Claude Code only registers MCP servers at session start, and a freshly-installed ilens additionally needs the Claude app itself relaunched so the new app process picks up the updated PATH. Close Claude app entirely, then start a new Claude Code session in the relaunched app — see the Heads up callout under Integrating with Claude Code for the full mechanics.

Appendix A: claude mcp add CLI

A programmatic alternative for users who'd rather not edit .mcp.json by hand:

claude mcp add ilens ilens -- --allow-root "C:\path\to\dlls"

The "double ilens" is intentional. The first is the MCP server alias — the same string that becomes the JSON key in .mcp.json. The second is the binary on PATH after install. The -- separator before --allow-root is required so claude mcp add does not consume --allow-root as one of its own options.
